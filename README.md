# mac-live

macOS 悬浮文字工具：把自定义文字浮在屏幕上，供直播 / 录屏 / 讲课使用。

原生 **SwiftUI + AppKit** 实现，无第三方依赖，单条命令即可构建。

最有意思的功能是 **直播模式**：文字只出现在直播画面里，**你自己的屏幕完全看不到**——适合直播时把提示语/口播文案"只给观众看"。

---

## 功能

- **透明无边框悬浮窗**：只显示文字本身，没有窗口框、没有背景。
- **始终置顶 + 全空间可见**：切换桌面空间、其他 App 全屏时都不会消失，方便被采集。
- **文字自定义**：多行文本、系统字体 / 任意已装字体、字重、字号、字间距、行距、左中右对齐。
- **样式**：文字颜色、描边（宽度 / 颜色）、阴影（模糊 / 偏移 / 颜色）、整体透明度。
- **背景底板**：可选圆角底板，适合浅色画面。
- **锁定位置**：一键锁定，锁定后不可拖动且鼠标穿透，直播中不会被误拖。
- **编辑模式 / 鼠标穿透**：编辑时可直接拖动定位；关闭后不影响下层软件操作。
- **文案预设**：保存多组常用文案（欢迎、关注我、稍等…），一键切换。
- **菜单栏入口**：显示 / 编辑模式 / 锁定 / 直播模式一键开关，快速重置位置。
- **状态自动保存**：位置、样式、文案、直播设置全部本地记忆，重启即恢复。
- **直播模式（重点）**：把文字搬到一块系统虚拟显示器上，自己的屏幕保持干净；直播软件采集那块屏即可，**不需要绿幕**（也保留了绿幕与窗口采集两种接线方式）。

## 系统要求

- macOS **14.0 (Sonoma)** 或更高
- Apple Silicon 或 Intel（本项目在 Apple M2 + macOS 14.6 上开发与验证）
- 构建需要 Xcode Command Line Tools（`xcode-select --install`）
  - 若 `swift` 报 `xcrun: invalid active developer path`，说明 `xcode-select` 指向了不完整的 Xcode，可显式指定：
    `DEVELOPER_DIR=/Library/Developer/CommandLineTools ./scripts/build.sh`

## 构建与运行

```bash
git clone https://github.com/<your-name>/mac-live.git
cd mac-live
./scripts/build.sh release --run     # 编译 + 打包成 dist/mac-live.app 并启动
```

产物是 `dist/mac-live.app`，可以直接双击，也可以拖进「应用程序」。

> **关于签名**：`scripts/build.sh` 会自动优先用本机「Apple Development」证书签名，找不到则回退 ad-hoc。
> 这不是必须的，但系统权限（如「屏幕录制」）是按签名身份记账的：**ad-hoc 签名每次重新构建都会让授权失效**，
> 用证书签名则可以一直沿用。也可手动指定：`SIGN_IDENTITY="<证书名>" ./scripts/build.sh`

## 基本使用教程

1. **启动**：App 启动后会打开设置窗口，同时屏幕上出现悬浮文字（默认在屏幕顶部中间）。
2. **写文案**：「文字」页输入内容，回车即换行（支持多行）；下面可调字体、字重、字号、字间距、行距、对齐。
3. **调样式**：「样式」页设置文字颜色、描边、阴影、背景底板、整体透明度，以及窗口置顶级别。
   - 直播建议：白字 + 深色描边（默认），浅色画面可再开背景底板。
4. **定位**：打开顶部「编辑模式」，直接拖动悬浮文字到想要的位置；位置定好后关闭「编辑模式」或打开「锁定位置」（此时鼠标穿透，不会挡住你操作别的软件）。
5. **常用文案**：「预设」页可以保存多组文案，直播中一键切换。
6. **日常开关**：菜单栏图标里可以快速切换 显示 / 编辑模式 / 锁定位置 / 直播模式 / 重置位置。

到这里，用直播软件或录屏工具采集显示器画面，观众就能看到这行文字了。

## 直播模式：只让观众看到，自己屏幕保持干净

原理：App 用系统私有 API 创建一块**虚拟显示器**（默认 1920×1080），把文字铺到那块屏上。
这块屏在你自己的显示器上不存在，所以你什么都看不到；直播软件从它那里取画面给观众。

打开路径：设置窗口 →「直播」页 → 选择合成方式 → 打开「开启直播模式」。

### 方式 A：画面合成（默认，推荐，不需要抠像）

App 用 ScreenCaptureKit 采集你的屏幕，把文字合成进去，整幅输出到虚拟屏。

1. 合成方式选「**画面合成（原画面 + 文字，推荐）**」。
2. 首次会提示缺少「屏幕录制」权限：点「申请权限」→ 到 系统设置 → 隐私与安全性 → 屏幕录制 里勾选 **mac-live** → 重启 App。
3. 直播软件里添加「显示器采集 / 屏幕采集」，选择 **「mac-live 虚拟屏」**，作为唯一的整屏画面来源。
4. 不需要任何抠像滤镜，观众看到的就是"你的屏幕 + 悬浮文字"；你自己的屏幕依旧干净。

可调项：**适配方式**（等比适应留黑边 / 填满裁剪 / 拉伸）、**帧率**（30 / 60）、**画面里隐藏本 App 窗口**。
设置页下方有**实时预览**，显示观众实际看到的样子。

### 方式 B：绿幕抠像（直播软件需支持色度键）

1. 合成方式选「纯色抠像（绿幕）」，打开「使用纯色底」并选择底色（默认纯绿）。
2. 直播软件添加「显示器采集」选「mac-live 虚拟屏」，加「色度键 / 抠像」滤镜，放在画面之上。

### 方式 C：窗口采集（零权限，取决于软件是否保留透明通道）

1. 合成方式选「纯色抠像」，把「使用纯色底」**关掉**（窗口变透明）。
2. 直播软件添加「窗口采集」，选 **mac-live**（可能显示为进程名 `mac-live`），铺满画布。
3. 若画面出现黑底方块，说明该软件不保留透明通道，请改用方式 A。

### 注意（直播模式）

- **务必保持 App 运行**：关闭「直播模式」或退出 App，虚拟屏会立即消失，直播软件里的采集源会失效。
- **鼠标可能移进那块看不见的屏**（它会扩展桌面）。往那个方向推鼠标，指针会"消失"进虚拟屏，这是正常的；可在「系统设置 → 显示器」调整两块屏的排列，或随时关掉直播模式。
- **不要把虚拟屏设为「镜像」**，否则文字会同时出现在你自己的屏幕上，就失去意义了。
- 默认会把本 App 的窗口从采集画面里去掉（避免观众看到设置窗口），可在「直播」页关闭。
- 1080p 画面下字号建议 60～120，改完看下方预览确认。
- 绿幕方式下文字 / 描边 / 底板会按不透明渲染（否则会与底色混色被一起扣掉）。

## 常见问题

**Q：开启直播模式后画面是黑的 / 提示缺少「屏幕录制」权限？**
到 系统设置 → 隐私与安全性 → **屏幕录制** 勾选 mac-live，然后重启 App。
若之前授权过却仍失败（常见于 App 刚重新构建），把 mac-live 从列表里**移除后重新添加**。

**Q：每次重新构建后都要重新授权？**
ad-hoc 签名的授权会随每次构建失效。用证书签名即可（见上文「关于签名」）：
`codesign -dv -r- "dist/mac-live.app"` 看「指定要求」里是否含 `cdhash`，含则每次都要重授权。

**Q：画面静止时看起来"卡住"？**
这是系统行为：ScreenCaptureKit 只在画面有变化时才投递新帧，屏幕不动时画面本来就不变。
**鼠标指针由 App 自己按 60Hz 绘制**，所以指针会一直顺滑跟随。

**Q：直播软件里找不到 mac-live 窗口？**
窗口采集列表里它叫 `mac-live`（也许显示为进程名）。可先临时关掉「直播模式」，窗口会回到你自己的屏幕上、看得见，确认能选到后再打开直播模式。

**Q：光标跑到屏幕外面了？**
你推到了那块看不见的虚拟屏上。关掉直播模式即可，或在「系统设置 → 显示器」把它排到不顺手的方向。

**Q：能用 OBS 吗？会议软件（腾讯会议 / Zoom）行不行？**
方式 A 走的是标准「显示器采集」，任何能采集显示器的软件都能用。方式 B 需要该软件支持「色度键 / 抠像」。

## 开发 / 调试参数

```bash
BIN="dist/mac-live.app/Contents/MacOS/mac-live"

# 离屏渲染效果图（普通模式）
"$BIN" --render-preview --out /tmp/preview.png
# 离屏渲染直播模式画面：抠像 / 透明 / 画面合成（可用 --fit-fill、--fit-stretch 验证适配）
"$BIN" --render-preview --live --chroma --out /tmp/chroma.png
"$BIN" --render-preview --live --composite --out /tmp/composite.png
# 校验自己绘制的鼠标指针落点（数值误差应为 0）
"$BIN" --cursor-check --out /tmp/cursor.png

# 启动后把悬浮窗真实状态写入 /tmp/maclive-window.log 再退出
open -n "dist/mac-live.app" --args --dump-window
# 额外在 N 秒后翻转「直播模式」，用于验证进出直播模式
open -n "dist/mac-live.app" --args --dump-window --toggle-live-after 1.5
# 实测屏幕采集的帧投递行为（需要屏幕录制权限）
open -n "dist/mac-live.app" --args --capture-probe 4
```

（这些开关既是自测手段，也是无屏幕录制权限环境下唯一能验证渲染/窗口状态的方式。）

## 项目结构

```
Sources/MacLive/
  App/        应用入口、生命周期
  Model/      配置模型（Codable + 默认值合并，兼容旧存档）、持久化
  Render/     文字渲染（描边/阴影/底板）、鼠标指针几何换算
  Views/      设置界面、菜单栏、画面预览
  Window/     悬浮窗面板、虚拟显示器、屏幕采集、直播模式状态
  Support/    自测 / 探针（离屏渲染、窗口诊断、采集帧统计、指针校验）
scripts/build.sh   编译 + 组装 .app + 签名
Resources/Info.plist
```

## 已知限制

- **虚拟显示器用的是系统私有 API（`CGVirtualDisplay`）**，未来 macOS 版本可能失效；失效时 App 会自动关闭直播模式并在「直播」页给出提示，此时可退回普通悬浮窗模式。
- 未做代码签名 / 公证（自行构建即可，本地运行不受影响）。
- 暂无应用图标、全局快捷键、竖排文字、文字镜像（提词器）、多个悬浮窗、图片 / GIF 叠加。
- 直播模式需要「屏幕录制」权限；画面会多 1～2 帧延迟。
